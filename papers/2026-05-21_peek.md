## 1) 一句话 Why-read
- **Key claim/contribution + key observation：** PEEK 提出 "context map" 作为 agent 对 recurring external context 的 **orientation cache**（类比 CPU cache）：一个固定 token budget (1024) 的 prompt-resident artifact，通过 Distiller→Cartographer→Evictor pipeline 维护。在 OOLONG 和 CL-bench 上比 SOTA prompt-learning (ACE) 高 +6.3–15.0% 且省 1.7–5.8× cost。**Key observation**: 区分 "orientation knowledge about context"（可跨任务复用）与 "task-level strategy"（prompt learning）是关键设计决策。

## 2) CRGP 拆解 Introduction
### C — Context
- LLM agent 越来越多地反复操作 long external context（document corpora, code repos）。
- 现有 context management 方法：trajectory 保留（shared chat）、raw material access（RAG/offloading）、task-level strategy（prompt learning/ACE）。

### R — Related work
- 作者提出 2×2 design space：**Active vs Passive** × **Agent/Task State vs External Context State**
  - Prompt learning / agent skills = Active + Agent State
  - RAG / compaction = Passive + External Context State
  - Shared chat / history compaction = Passive + Agent State
  - **空白象限**: Active + External Context State → Context Map (PEEK)

### G — Gap
- 没有方法 actively maintain 一个关于 recurring external context 本身的 reusable orientation knowledge artifact。
- Raw trajectory 是 noisy 的；RAG 不维护 curated understanding；prompt learning 优化 task strategy 而非 contextual knowledge。

### P — Proposal
- **Context map**: constant-sized (B=1024 tokens) prompt-resident artifact，包含 5 sections：
  - Context Roadmap, Context Understanding, Domain Constants, Reusable Results, Parsing Schema
- **Programmable cache policy** (3 modules):
  1. **Distiller**: 从 agent trajectory 提取 transferable contextual knowledge（排除 task-specific facts）
  2. **Cartographer**: 转化为 structured edits（section-level, stable item IDs）
  3. **Evictor**: priority-based eviction 维持 fixed token budget
- Cache 可在 m=1 query 后 freeze。

## 4) Experiments
### 4.1 Experimental setup
- **Datasets:** OOLONG (3 hardest splits: trec_coarse, agnews, yahoo) + CL-bench (context learning, up to 12 tasks per context)
- **Base LM:** GPT-5-mini (main), GPT-5.5 / Qwen3-Coder-Next-FP8 (generalization)
- **Backbone Agent:** RLM (main), OpenAI Codex (generalization)
- **Baselines:** Base RLM, RLM+Shared Chat, RLM+RAG, RLM+Compaction Agent (MemAgent), RLM+ACE (SOTA prompt learning)
- **Metrics:** OOLONG score (0.75^|y-ŷ| for numerical, EM otherwise); CL-bench solving rate + rubric accuracy (GPT-5.1 judge)

### 4.2 Main result table

| Method | TREC-Q | AGNews | Yahoo | CL-Solve | CL-Rubric |
|---|---:|---:|---:|---:|---:|
| RLM (baseline) | 30.3 | 46.5 | 23.0 | 14.0 | 54.5 |
| RLM + Shared Chat | 32.0 | 49.6 | 23.0 | 12.0 | 51.3 |
| RLM + RAG | 36.6 | 63.1 | 29.0 | 14.0 | 55.6 |
| RLM + Compaction (MemAgent) | 42.0 | 49.5 | 30.0 | 20.0 | 54.6 |
| RLM + ACE (SOTA) | 48.8 | 61.6 | 42.0 | 20.0 | 53.5 |
| **RLM + PEEK** | **58.1** | **69.4** | **57.0** | **26.0** | **63.4** |
| Delta vs ACE | +9.3 | +7.8 | +15.0 | +6.0 | +9.9 |
| Delta vs Base | +27.8 | +22.9 | +34.0 | +12.0 | +8.9 |

**Cost:** PEEK 比 ACE 省 1.7–5.8× (OOLONG), 1.4× (CL-bench)。Iterations: PEEK 比 ACE 少 93–145 iterations。

### 4.3 Analysis experiments

- **现象1：** Shared Chat 在 CL-bench 反而降低 performance (-2.0 solve, -3.2 rubric)。
  **解释（作者）：** raw trajectory accumulation 变成 noise，degrades rather than aids。
  **【标注】** "什么都记"不如"选择性记 orientation knowledge" — 对 agentic memory 设计的 first-principle。

- **现象2：** No Eviction (freeze at budget) 仍大幅优于 baseline (+21.7 TREC)，但比 full PEEK 低 ~10%。
  **解释（作者）：** context map 本身有价值 even without maintenance; priority-based eviction 额外贡献 +10.2% avg。
  **【标注】** "有 index 就比没有好" — map 的存在 > map 的精确维护。但持续维护仍有显著 marginal value。

- **现象3：** Monolithic Update（合并 Distiller+Cartographer 为单次 LLM call）比 full pipeline 低 -7.7% avg。
  **解释（作者）：** 不分离 diagnosis 和 edit planning 导致 task-specific facts leak + noisy duplicative updates。
  **【标注】** **关键设计决策**：分离 "what to extract" 和 "how to edit" 是防止 cache pollution 的核心。

- **现象4：** Cache size B ∈ {512, 1024, 2048} 都大幅优于 baseline，B=1024 最优。B=2048 在 TREC 上反而下降 -13.5 vs B=1024。
  **解释（作者）：** 存在 sweet spot；太大引入 noise，太小丢失信息。
  **【标注】** B=2048 下降可能是 attention dilution — 值得进一步研究。对 memory budget 设计有直接参考意义。

- **现象5：** 在 Codex agent（production-grade）上 gains 更大。
  **【标注】** generalization signal 强 — 不依赖特定 base LM。

## 5) Why it matters for our work

**直接相关性极高（5/5）：**

1. **Agentic memory architecture**: PEEK 的 context map 本质是一种**新型 agent memory** — 不是 episodic memory（trajectory），不是 semantic memory（knowledge base），而是 **procedural/navigational memory** about how to orient in a specific context。这填补了现有 memory taxonomy 的空白。

2. **设计原则提炼：**
   - "Small curated artifact in prompt" >> "dump everything in context window"
   - 分离 Distiller（what to remember）和 Cartographer（how to organize）防止 cache pollution
   - Fixed budget + priority eviction = 可控 memory footprint

3. **Cache metaphor 可扩展性**: Distiller→Cartographer→Evictor pipeline 可直接 adapt 为 memory consolidation mechanism。

4. **与 KV-cache 正交**: 论文明确指出 context map 是 agent-level artifact（curated meaning），与 model-level KV-cache optimization 互补。

5. **Multi-session agent 启发**: 每个 project/repo 维护独立 context map 作为 orientation cache — 这正是 Hermes Agent 的 AGENTS.md / MEMORY.md 在做的事情！
